# R035 Praneeth Centering Case (2026-09-07)

## Background

After the 2026-09-05 landscape-aware centering fix (commit `1a90501`),
Anthony's Ester-reviewed R035 false positives were confirmed gone, but
Praneeth still produced 4 live P035 findings (figures on physical pages 67
and 72, tables on physical pages 69 and 100). A prior audit pass this session
could not determine whether these were a reintroduced instance of the
reviewed false positive or unrelated, unreviewed findings.

## What Ester actually said

No file in this repository stores a verbatim reply from Ester for R035 —
the tracked `R035_Ester_Auditor_Feedback.xlsx` and
`docs/evaluation/ester_feedback/live_sheet_pending_content.json` were both
generated by commit `3816fcc`, which predates the actual fix commit
(`1a90501`) by several commits, and describe the case that was *sent* to
her (Praneeth, physical page 29, a figure caption), not her reply. Circumstantial
evidence is strong: page 29 no longer appears among Praneeth's current P035
findings at all, consistent with that specific reviewed case having been
fixed by `1a90501`. But no independently stored verbatim decision text
confirms it.

**Conclusion: Praneeth's 4 remaining findings (pages 67, 69, 72, 100) are not
the reviewed case.** They are on different pages, were never sent to Ester,
and per project policy an unreviewed finding is not automatically a false
positive.

## The bug found (independent of any Ester text)

Diagnosing each of the 4 findings' geometry directly:

| Page / float | Center delta vs 18pt tolerance | Assessment |
|---|---|---|
| 67, figure | 22.2pt | Plausibly genuine — real graphic block, modest overflow |
| 69, table | 18.4pt | Boundary — real text-table union, barely over threshold |
| 100, table | 27.4pt | Plausibly genuine — real graphic/table union |
| **72, figure** | **114.3pt** | **Confirmed bug** |

Page 72's massive delta traced to a real defect in
`check_pdf_figure_table_layout` (`src/njit_auditor/rules/pdf_figure_table_layout.py`):
when no qualifying graphic block was found above the figure's caption, the
code fell back to the nearest text cluster and measured *that* for
centering. The text cluster in this case was made of small fragments (axis
labels/annotations extracted as separate text blocks) with no relationship
to where the actual embedded image sits.

## Fix

Commit `6facf49`: when the figure-centering check falls through to a
text-based fallback (no confirmed graphic block found), skip the centering
check entirely rather than measuring text that isn't the image. This is a
structural fix, not a tolerance change — `CENTER_TOLERANCE_PT` (18pt) and
`LANDSCAPE_CENTER_TOLERANCE_PT` (50pt) are unchanged. Other figure checks
(caption-placement) on the same fallback path are unaffected.

Result after the fix: page 72's finding is gone; pages 67, 69, and 100 are
untouched (they use a confirmed graphic or text-table body, not the buggy
fallback) and remain as unreviewed, plausibly genuine findings — not
suppressed, since suppressing them without evidence would risk hiding a real
violation.

## Test coverage added

`tests/test_rules/test_r035.py::test_r035_figure_text_fallback_not_used_for_centering` —
synthetic reproduction (two off-center single-line text fragments above a
figure caption, no graphic block present at all); confirmed to fail without
the fix and pass with it.

`tests/test_pdf_rules.py::test_p035_off_center_figure_body_warns` was itself
relying on the same fallback bug (it represented a figure's body with text
rows, not a real image) and has been rebuilt to use a real embedded raster
image, matching the project's established pattern for other R035 figure
tests in the same file.
